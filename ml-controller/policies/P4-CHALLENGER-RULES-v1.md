# 冠軍／挑戰者評判規則 v1（封存版）

來源：R30 第三節（內層判定）與第五節，依 R31（角色）、R32（第四節第 4 點）修訂後的全文。R17 第一節（SHA `e8361d229e7810f45ea693f62acdd04f57c3f037e4c2be9edf78c5504eb0cb3d`）與權重時點補充（SHA `be97f6c8b6105eaeac7436ee570aa568d00671686fb8cf8f8f0cc546914ac7f9`）中的主要指標定義，沿用並抄錄於第四節。

封存後不得修改；任何修改須另立新版本與新 SHA。本檔須在**登錄第一個挑戰者之前**、**計算任何回填或外層績效之前**綁定登錄表。

## 一、角色（部署時）

| 角色 | 組合 |
|---|---|
| 冠軍 | 案 A 月訓後的 P6-a，線性校準（B）；產生 pending buys |
| 挑戰者 | 舊 L4 c53e1d53（保留完整舊上游鏈：舊 L3＋c53）；P6-a 原始分數（A） |
| 不登錄 | P6-a 九段 EB 校準（C），在其求解問題解決前不登錄 |
| D | 候選池等權基準，只做解析計算，不模擬成交 |

A／B／C 是校準屬性，不是固定 ID。之後可隨時加入新挑戰者，條件見第二節。

## 二、挑戰者加入條件

已凍結（各元件 checksum 已記錄），並通過內層判定：

- **評估方式**：w4／w5／w6 前推窗口，每個窗口只用該窗口之前、標籤已成熟的資料訓練。
- **統計方法**：日配對差，5 個交易日循環區塊 bootstrap，5,000 次，95% 區間。
- **規則**：相對不含該改動的版本，rank IC 配對差的區間不整段為負，**且**前 5 名超額配對差平均 > 0 → 採用；否則維持現行。不得事後更換指標。

登錄表須記錄：各元件 checksum、signal_date_max、label_known_at_max、內層判定收據、加入時間、校準方式、獨立帳戶 ID。

## 三、外層日（每個挑戰者各自計算）

訊號日 d 計入某組合的外層日，須同時滿足：

1. 該組合所有可訓練元件的訓練標籤最晚已知日 < d（現行 `validate_bundle` 契約）。案 A 下為 label_known_at_max = 10/1，外層自 10/2 起。
2. d 的輸入可用當時資料重建。HMM 等共用市場環境，只能使用 `computed_at` 早於次一交易日開盤的版本；晚於開盤才產出者，依紀錄判定，不補造。
3. 10/13（五日風險）、10/14（canonical 狀態）須從當時可知的價格重建，有收據才合格。
4. d 的五日標籤已成熟。

另外：

- 回填日標示為 retrospective holdout，保留 posthoc 註記。
- 回填日與即時日都計入。
- 合格認定只看資料與事故紀錄，不看報酬。認定須在計算任何績效之前完成並記錄 SHA，之後不得剔除。
- 兩組合比較時，只用兩者共同的合格日。
- 祖先圖收據（由實際 checkpoint 與訓練資料生產者列出）須在計算回填績效之前完成並封存。

## 四、主要指標

> Σ(次一交易日開盤前已寫入收據的目標權重 × 個股五日報酬) ÷ Σ目標權重 − 同日全候選池等權五日報酬

- 五日報酬：次一交易日 adjusted open 至第五交易日 adjusted close。
- 目標曝險為 0 的日子記缺值，不記 0。
- 實際持股與成交的歸因另列，標明「成交後歸因」，不取代主要指標。

## 五、評判

由使用者發起時執行（第一次在 2026-10-30 收盤後），使用當時累積的全部合格日，不設固定天數。

1. **資格**：每個挑戰者相對冠軍，計算主要指標的日配對差（5 日循環區塊 bootstrap、5,000 次、95%）。平均 > 0 且區間不整段為負 → 合格。
2. **挑選**：合格者中取平均最高者。若與第二名的配對差區間跨 0，取與冠軍不同的元件數較少者；相同時依 A > B > C。
3. **對候選池**：被選者相對 D 的主要指標平均須 > 0；否則不換，回報並檢討 L4 架構。
4. **營運檢查**：求解成功率、市值加權持有交易日數，都不得低於冠軍。持有天數用開盤前目標權重路徑計算，冠軍用其存檔的目標權重。不通過即不換，並回報原因。
5. **結果**：通過 → 建議更換，由使用者確認；走現有的發布、讀回、回滾流程，並同時檢查 L3／L4 identity。未通過者繼續累積，下次評判再算。
6. **報告**：列出評判日期、當時挑戰者數、各自日數、每臂的主要指標與配對區間。

## 六、晉級後與降級

- 被選者成為冠軍；原冠軍轉為挑戰者，繼續影子記錄。若之後被反超，以同一規則換回。
- 自動降級只用於服務異常：推論或配置失敗、checksum 不符、pending buys 未產出。發生時回到上一個正常的冠軍並通知。不依績效自動降級。
- 切換正式 pointer 只能由現有唯一的切換 owner 執行，並經使用者確認。
